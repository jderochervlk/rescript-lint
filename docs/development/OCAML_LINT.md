# OCaml implementation lint

`make lint` checks first-party OCaml without changing sources. `make check`
adds the same gate to build, OCamlformat, and tests; the shared GitHub Actions
Linux job installs development dependencies and runs that command. Install with
`opam install . --deps-only --with-test --with-dev-setup --yes`. Node.js 24 or
newer and a POSIX shell are required for the adapter; CI runs it on Linux. Zanuda 2.1.0 is pinned in `dune-project` and
Dune-generated Opam metadata under `with-dev-setup`; consumer installs and npm
runtime dependencies do not require it.

## Compatibility and discovery

Zanuda 2.1.0 installs and runs with OCaml 5.5.0, Dune 3.24.2, OCamlformat 0.29.0,
the existing PPX graph, and the pinned Bisect coverage tooling. Its own
`-version` output incorrectly reports `version: version: 2.0.0`; the adapter
checks the installed Opam package version instead. Zanuda's own development
formatter constraint does not apply when installing it as this project's
development dependency.

`@check` produces the `.cmt`/`.cmti` artifacts needed for analysis. The standalone
target also builds the small `scripts/lint/artifact_manifest.exe` helper.
Dune 3.24.2's `dune describe workspace` omits `(test ...)` executables, so invoking
Zanuda directly would miss tests. The helper reads compiler metadata to associate
artifacts with their original source paths. The adapter gives Zanuda those
associations through a restricted `dune describe workspace .` shim; it does not
infer wrapped module names or change Dune test stanzas.

Only `.ml`/`.mli` files present in `lib/`, `bin/`, `test/`, and `scripts/` are
selected. `lib/unsafe_apis/banned_runtime_data.ml` is generated by the runtime
inventory generator and is explicitly excluded in `scripts/lint/lint.mjs`.
Vendor copies, generated empty test interfaces and library wrappers, `_opam/`,
and unrelated artifacts are excluded before analysis, rather than filtering
away their findings afterward. Each selected source must have exactly one full,
current typed artifact; its compiler source digest must match the original file.
Missing, duplicate, stale, or unreadable artifacts fail the gate. New generated
sources require a reviewed addition to the explicit exclusion list.

Zanuda reports findings with exit status zero. The adapter parses its supported
RDJSONL output and returns 1 for findings, 2 for a tool/configuration failure,
and 0 only for a clean run. It rejects malformed or out-of-scope diagnostics,
missing output, process failures, and stderr (including skipped-analysis
messages). It never matches free-text messages to decide whether a run passes,
and never invokes `-fix`. Adapter tests run as part of both lint targets.

## Rule policy

`.zanuda` disables reviewed rules from the pinned version. The adapter validates
option names against Zanuda's rule metadata to catch typos. Formatting remains
OCamlformat's responsibility; enabled compiler warnings remain fatal.
Compiler warning 39 is explicitly enabled to catch unnecessary `rec`, which
Zanuda 2.1.0 does not check for functions.

| Enabled rule | Purpose |
| --- | --- |
| `if_bool`, `match_bool` | Redundant boolean expressions and matches |
| `wrong_ignoring` | Require explicit types for discarded non-unit results |
| `mutability_check` | Flag refs, hash-table uses, and mutable record fields for review |
| `manual_map`, `manual_fold` | Recognize direct implementations of standard list transformations |
| `list_length_comparisons` | Avoid full list traversal for length comparisons |
| `string_concat_fold` | Avoid repeated concatenation in a list fold |
| `monad_laws_simplify` | Redundant option/result transformations |
| `var_should_not_be_used` | Suspicious uses of deliberately ignored names |
| `dont_disable_all_warnings` | Prevent wholesale masking of compiler warnings |

`on_offer_prologue` and `on_offer_epilogue` remain enabled as Zanuda's internal
iterator helpers, not style rules. Avoid adding inline Zanuda disables: reviewed
exceptions belong in the checked configuration described below.

| Disabled rules | Reason |
| --- | --- |
| `top_file_license`, `no_docs_parsetree` | Repository licensing and documentation conventions are reviewed separately |
| `camel_cased_types`, `camel_extra_dollar`, `record_punning`, `format_module_usage` | Naming, spelling, and presentation preferences are outside this gate |
| `ambiguous_constructors`, `misc_aggregate_defs` | Legitimate domain variants and declarations do not need mechanical restructuring |
| `eta_reduction`, `propose_function`, `tuple_matching`, `use_guard_instead_of_if`, `use_match_instead_of_equality` | Preference checks can obscure exhaustive AST traversal and existing explicit interfaces |
| `mutually_rec_types` | Splitting declarations can alter interface/type ordering; unnecessary function recursion is covered by warning 39 |
| `forbid_many_nested_if_expressions` | Function cohesion and AST match complexity remain architectural review judgments |
| `exc_failwith`, `exc_error_swallowing` | Expected exceptions, test assertions, and boundary translation require contextual review |
| `expect_tests_no_names`, `no_toplevel_eval` | Test setup and the executable entry point have legitimate effects |
| `physical_equality` | AST node identity is intentional in analysis and identity tests |
| `list_fusion` | Combining transformations can change callback/effect ordering |
| `string_concat` | Small fixed concatenations are clearer than mandatory buffer/combinator rewrites |
| Filesystem/interface check (`-no-check-filesystem`) | Existing `.ml`/`.mli` boundaries follow repository conventions; this is passed explicitly to Zanuda |

The initial full scan was classified before integration. The enabled-policy
fixes replace 36 `ignore` calls with explicitly typed wildcard bindings and
simplify two boolean branches in graph reachability. Traversal, diagnostic
ordering, tail calls, public interfaces, and consumer behavior are preserved.
No vendor sources or coverage thresholds change.

## Narrow mutation exceptions

Follow [AGENTS.md](../../AGENTS.md): mutation is permitted at effect boundaries,
when a library contract requires it, or for a demonstrated performance benefit.
Current exceptions cover runtime signal/cache/transport state, test callback
instrumentation, and local accumulators used by unit-returning AST/reporting
callbacks. Changing those callback contracts would be a separate architectural
change, rather than a lint cleanup.

`.ocaml-lint-exceptions.json` records the rule, file, exact diagnostic line,
trimmed source text, and reason. It only accepts `mutability_check` exceptions.
A new mutation on another line, or replacement code on an excepted line, remains
subject to the gate. Stale, unused, duplicate, out-of-scope, or unjustified
exceptions fail. Multiple typed diagnostics can refer to one reviewed site.
There is no whole-file or whole-rule suppression.

Keep AST traversal order, callback effects, and stack safety when applying idiom
changes; do not blindly apply suggested rewrites.

To handle a finding, first remove avoidable mutation. If a permitted exception
is necessary, add only the reported site with its exact source text and explain
the callback contract or effect boundary in the reason. For performance cases,
include measurement evidence in the change description. Keep the exception
current when moving code, and remove it when the mutation disappears. Run
`make lint`, then `make check`. Function size, semantic cohesion, architectural
purity, and legitimate traversal recursion still require review under AGENTS.
